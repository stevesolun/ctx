# Skill map

Use this as a routing reference, not a mandatory pipeline.

| Need | Likely skill | Notes |
|---|---|---|
| Stress-test an idea | `grilling`, `grill-me`, `grill-with-docs` | Choose the stateful variant only when durable domain notes are useful. |
| Resolve a design question with evidence | `prototype`, `research` | Prototype behavior or UI; research facts and sources. |
| Plan an unusually large, unclear effort | `wayfinder` | Use only when one session cannot expose the route. |
| Turn settled thinking into work | `to-spec`, `to-tickets` | A spec is optional; tickets help when work needs coordination. |
| Implement or test-first build | `implement`, `tdd` | Invoke TDD when test-first development is the user's chosen approach. |
| Review a change | `code-review` | Compare the diff with repository standards and the intended behavior. |
| Diagnose a difficult failure | `diagnosing-bugs` | Establish useful feedback before committing to a theory. |
| Resolve Git conflicts | `resolving-merge-conflicts` | Preserve intent and escalate irreconcilable ambiguity. |
| Improve architecture or language | `improve-codebase-architecture`, `codebase-design`, `domain-modeling` | Select architecture, interface, or domain vocabulary based on the question. |
| Triage incoming work | `triage` | Use the repository's configured tracker conventions. |
| Carry context to another session | `handoff` | Reference existing artifacts instead of copying them. |
| Build a learning workspace | `teach` | Persist artifacts only when multi-session learning benefits from them. |
| Configure or maintain skills | `setup-matt-pocock-skills`, `writing-great-skills` | Setup should follow existing repository conventions. |
